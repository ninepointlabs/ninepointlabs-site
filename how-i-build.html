How I build

I don't write the code. I run the team that does.

People assume a site full of repos means a person who codes all day. I don't. I know what I want, I can tell when it's wrong, and I'm stubborn about quality. The typing is done by AI agents I direct. This page is the honest version of how that works.

The team

Three agents, three jobs

They run on Hermes Agent, an open-source framework that lets each one keep its own memory, tools, and personality, and message the others. I talk to them from a bar widget on my desktop, from a chat app, and occasionally by yelling at a terminal.

1The coordinator

Keeps my notes, calendar, and journal. Turns "I want X" into a brief the other two can act on, sequences the work, and tells me when something's ready to look at.

2The coder

Owns GitHub. Writes the code, writes the tests, opens the commits, fixes what breaks in CI. Blunt about bad ideas, which I've come to appreciate. Built this site.

3The systems agent

Touches the machine. Deploys plugins, restarts services, checks logs, tells me when something on the box is actually broken versus just looks broken.

The loop

What a normal day looks like

  1. I describe the thing in plain English.

    "The calendar widget should show the journal entry for the day you click." No specs, no tickets. If I can't explain it simply I'm not ready to build it.

  2. The coordinator turns that into a brief.

    What exists already, what must not change, who does which part, what "done" means. That brief is what the coder actually receives.

  3. The coder builds it and proves it.

    Real commits, real tests, real output. I've trained them hard on one rule: never tell me it works, show me the run. When the tooling can't reach something, say so.

  4. The systems agent puts it on the box.

    Copies the plugin, restarts the shell, reads the log. Some things it will not do without me in the room, like restarting the signer that holds my Nostr key.

  5. I use it. Then I complain.

    Most projects go through three or four rounds of "no, like this." That's the part only I can do, and it's where the taste comes from.

Guardrails

Rules I hold them to

No secrets in the loop

Agents never see a private key, a passphrase, or a password. Omostrich exists partly so they can post a note on my behalf without ever holding the key that signs it.

Show, don't tell

"Tests pass" means paste the test output. "Deployed" means paste the service status. A made-up result is worse than an honest failure, and they know it.

Nothing ships to my public face unseen

Work happens on branches. This redesign sat on one until I looked at it. Main is mine to merge.

Ask when it's a judgment call

Should this be one repo or two? Is this relay list a default or hardcoded? Those come back to me with options. Fixing a typo does not.

The honest part

Where it goes wrong

It's not effortless. Agents drift. They'll confidently describe a fix they never ran. They'll restructure something you didn't ask them to touch. A background service silently exited clean one afternoon because nobody had written reconnect logic, and the cache sat stale for sixteen hours before anyone noticed. Every one of those became a rule above.

What I can say is that this is how a semi-retired dad who delegates the coding ships a Linux desktop plugin ecosystem, a Nostr signer, and a paid product, and still makes Tae Kwon Do with his daughters. I'd rather be honest about the method than let you assume I'm something I'm not.

Tooling

What's under it

Agents
Hermes Agent, with Claude Code and Codex as delegated coding backends when a task calls for them.
Desktop
Omarchy Linux on Arch. Most plugins here are for its Quickshell bar.
Memory
Each agent keeps notes across sessions, plus an Obsidian vault they can read and write. That's how "the thing we did last week" works.
Publishing
Agents can post to Nostr through Omostrich's MCP server, only when I ask, only that text. No scheduling, no autopilot.
This site
Plain HTML and CSS, one tiny Node script to stamp the header and footer, GitHub Pages. No framework.
